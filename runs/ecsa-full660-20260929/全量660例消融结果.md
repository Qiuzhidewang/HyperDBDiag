# ECSA 全部 660 例消融与重复检查结果

本轮已完成全部 660 例的统一对照，以及预先固定的 60 例重复检查。新增 718 次模型调用，全部 2,100 个逻辑决策完成并重新校验；31 项相关测试通过。论文、图片、历史实现和旧实验报告未改动。

## 结论

1. **本地判别具备独立诊断价值。** 不使用 LLM 时，校准后本地读出为 546/660，Exact 82.73%，相对超图首选的 57.58% 提高 25.15 个百分点。原本地规则若真正直接读出，其成绩也达到 81.67%；旧表两行相同，不能解释为本地规则没有任何信息。
2. **完整组合在全量整体上优于本地单独使用。** 从 546 个正确提高到 580 个，Exact 87.88%，增加 5.15 个百分点；纠正 55 例、误伤 21 例，六个折的净正确数都增加。这里是总体与六折结论，不是每个子集、每个案例都更好。
3. **筛选对 LLM 的额外准确率收益很小，尚不能支持显著提升的表述。** 使用相同回退规则时，完整池为 578/660，保守池为 580/660：纠正 5 例、误伤 3 例，净增 2 例，即 0.30 个百分点。六折探索性区间跨零；本轮新增覆盖的 471 例两者同为 414 个正确，60 例重复检查两次也都 Exact 持平。
4. **保守筛选明显缓解了原筛选过窄的问题。** 相同全量协议下，原筛选 + LLM 为 82.12%，保守筛选 + LLM 为 87.88%，净增 38 个正确。与此同时，正确候选的条件保留率从 86.79% 提高到 99.21%。
5. **多根因子集仍有需要如实保留的不足。** 396 个双根因案例中，本地单独正确 340 个，完整组合正确 338 个，Exact 略降 0.51 个百分点；component F1 从 93.75% 提高到 94.28%。不能写成所有场景都优于本地单独使用。

## 统一主结果

所有行均在同一批 660 例上评分。F1 为根因分量的 micro-F1。共同回退是超图首选；完整组合的回退是校准后的本地输出。最后两行总分相同，但 7 个案例的预测不同：回退变化纠正 2 例、误伤 2 例、另有 3 例变化后仍错。

|---|---:|---:|---:|

| 原本地规则直接读出，无 LLM | 539/660 | 81.67 | 89.72 |
| 校准后本地判别，无 LLM | 546/660 | 82.73 | 90.12 |
| LLM 完整四候选池，无本地筛选 | 578/660 | 87.58 | 93.86 |
| 原本地筛选 + LLM，共同回退 | 542/660 | 82.12 | 89.95 |

| 完整组合，弃权时保留本地输出 | 580/660 | 87.88 | 94.08 |

## 60 例独立重复检查

在保守筛选实际改变候选池的 197 例中，按预先冻结的哈希规则每折选 10 例，共 60 例。对完整池和保守池各重新调用一次，共 120 次；没有选择较好的那次作为主成绩。

| 方法 | 主调用正确数/60 | 重复调用正确数/60 | 主调用 F1 (%) | 重复调用 F1 (%) |
|---|---:|---:|---:|---:|
| 校准后本地判别，无 LLM | 50 | 50 | 92.61 | 92.61 |
| LLM 完整四候选池，无本地筛选 | 52 | 53 | 94.58 | 95.10 |
| 保守本地筛选 + LLM，共同回退 | 52 | 53 | 95.00 | 95.52 |
| 完整组合，弃权时保留本地输出 | 51 | 52 | 94.00 | 94.53 |

完整池两次预测一致 58/60，保守池一致 59/60。两次筛选与完整池的 Exact 都持平，F1 分别约提高 0.42 个百分点。因此重复检查没有提供筛选稳定提高 Exact 的新证据。重复结果不是新增独立测试案例。

## 候选池与资源口径

| 候选池 | 平均候选数 | 正确候选保留数 | 相对于上游存在正确候选的条件保留率 |
|---|---:|---:|---:|
| 完整池 | 4.0000 | 636/660 | 100.00% |
| 原筛选 | 1.3167 | 552/660 | 86.79% |
| 保守筛选 | 3.4515 | 631/660 | 99.21% |

保守池平均从 4 缩减到 3.45，候选数减少 13.71%；463 例仍保留全部 4 个，165 例保留 2 个，32 例保留 3 个。上游有 24 例未包含正确候选，保守筛选另丢失 5 例；这 5 例中完整池 LLM 也全部预测错误，但不能因此认为丢失正确候选没有风险。
候选数减少不能等同于 API 成本同比减少。按每条路径的逻辑调用量统计，输入 token 只减少约 0.69%，输出 token 减少约 3.87%；共同证据仍保留，输出长度存在模型波动。以上包含共享决策，不是新增账单；没有据此声称显著成本或延迟收益。本轮并发为 8，前轮为 4，也不能直接比较跨轮耗时。

## 执行、回退与审计

718 次实际新增调用中：627 次有效选择、84 次有效弃权、5 次输出校验失败、2 次超时。全部按预先固定规则保留和回退，没有删除失败案例，也没有因预测较差重试。主实验 598 次新增调用，重复检查 120 次。原筛选中 451 个单候选案例的唯一候选与回退相同，无论何种有效结果预测均相同，故解析确定其预测，明确标为非模型调用。

主实验中影响完整池或保守池的执行失败涉及同样的 6 个案例，均为候选池和请求完全相同的共享调用。它们不可能产生筛选与完整池之间的预测差异；去除这 6 例做敏感性检查后，筛选仍纠正 5 例、误伤 3 例。其余 1 次失败属于重复检查。弃权属于有效模型行为。

独立输入审计验证全部 660 例的共同证据与保留候选卡内容一致，既有 567 个请求逐字节哈希一致，模型输入未包含测试答案或案例 ID，训练与测试案例分离，重复样本按冻结规则选择。输出审计重新验证全部 2,100 个决策和回退。31 项测试覆盖本地校准、候选约束、缓存映射、重复调用隔离、非等大小分组统计和共享失败推理。

## 需要继续注意的错误

下面列出共同回退对照中全部 5 个纠正与 3 个误伤，而非只选择成功案例。

| 案例 | 变化 | 正确根因 | 完整池 LLM | 保守池 LLM |
|---|---|---|---|---|
| case-0084 | 误伤 | missing_index+query_whole_table | missing_index+query_whole_table | query_whole_table |
| case-0575 | 误伤 | implicit_conversion+missing_index | implicit_conversion+missing_index | implicit_conversion |
| case-0602 | 纠正 | missing_index+record_lock | group_by+record_lock | missing_index+record_lock |
| case-0325 | 纠正 | implicit_conversion+missing_index | implicit_conversion | implicit_conversion+missing_index |
| case-0491 | 纠正 | query_whole_table | missing_index+query_whole_table | query_whole_table |
| case-0178 | 纠正 | order_by | missing_index+order_by | order_by |
| case-0415 | 纠正 | implicit_conversion | implicit_conversion+missing_index | implicit_conversion |
| case-0629 | 误伤 | missing_index+query_with_too_much_join | missing_index+query_with_too_much_join | query_with_too_much_join |

三个误伤均表现为 LLM 在仍含正确双根因候选的池中，选择了不含 missing_index 的单根因子集。它们不是正确候选被过滤掉，也不是候选编号或回退映射错误。证据卡将 broad_filtered_scan 明确列为上下文证据，不能仅凭一次宽扫描就断言缺失索引，因此也不能简单加入“必须保留 missing_index”的特判。全量结果中根因误报从 59 减至 54，漏报总数仍为 70；双根因子集的 Exact 小幅回落需要保留。
本轮没有为这些测试案例加入专门规则。后续若研究“LLM 删除本地支持的根因时需要更强证据”的接受条件，应对所有根因一视同仁，在训练内预先校准，再以独立保留数据评估；不得按这几个外层错误反复调整并只报告最好的版本。

## 稿件采用方式

这组结果可以作为统一协议的 ECSA 补充消融，用于分别回答无 LLM、无本地筛选和完整组合的效果。最有依据的表述是：本地模块提供有效的确定性候选读出，保守规则缩小候选池并保留大多数正确候选，LLM 在整体上进一步提升诊断表现；筛选对完整池 LLM 的准确率收益较小。不能写成显著、始终或在所有多根因场景中提升。

当前架构图和 ECSA 流程图不要求增加新模块。文字上需说明“不足以排除时保留候选，阈值仅由训练侧校准”、本地单独使用时的确定性读出，以及本轮统一全量覆盖的对照协议。旧表“本地模块不改变最终预测”的解释不能继续当作真正的本地读出消融。

若保留原主结果性能图的数据，这次应先作为明确标注新协议的受控补充实验；不能把 87.88% 直接当作原来预算受限运行的 65.45% 的同协议替换值。若采纳新实现与全量仲裁作为正文完整方法，性能表、性能图和实验设置必须同步一致；架构图和流程图可以保持。本文仅记录建议，未写回稿件。
