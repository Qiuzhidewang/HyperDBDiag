# 保守本地结构化判别器：训练侧校准实验

本实验保留“超图候选生成 → 本地结构化判别 → 受约束 LLM 仲裁”的思想、证据卡片和原有评分函数。没有修改论文、图片、旧判别器或历史实验报告。

**252/252 次新增模型调用已完成，无接口或输出校验失败。请先阅读 [实验结果与最小修改建议](实验结果与最小修改建议.md)。三组完整结果全部报告，未按成绩选择或删去某一组。**

## 代码改动

`src/conservative_evidence_judge.py` 提供可选的 `ConservativeEvidenceJudge` 和可审计的池筛选函数。

1. 原规则没有发现足够强的竞争候选时，真正保留完整候选池，不把“不足以改判”解释为“其余候选均可删除”。
2. 有足够强的本地判断时，保留超图首选、本地首选，以及与最高证据分数差距不超过校准值的候选；候选数量可以是 2、3 或 4，不固定为两个。
3. 直接语义证据规则保持原样；指标模式优势的改判阈值从固定 0.05 改为训练内交叉验证选择。候选阈值网格在外层评估前冻结。
4. 本地读出阈值先按训练 OOF Exact 选择，同分时优先更少改判；候选池阈值选择满足总体 99%、每个内层组至少 97% 的条件正确候选保留率的最小证据差距。该保留率为训练经验标准，不是理论覆盖保证。

`decide_pool(...)` 是新类的明确多候选接口。历史 `StructuredEvidenceJudge.propose(...)` 及其两候选接口完整保留，用于复现和旧流程比较。新实验入口实际调用同一模块中的 `describe_pool`、`calibrate`、`retain_pool`。

## 训练与评估边界

冻结 v11 数据仍为 660 例、6 个采集重复折、每折训练 550／评估 110。每个外层折内部再做全部 5 个训练组的交叉拟合；超图和证据画像都排除该内层验证组，也排除外层测试组。等价的模型拟合按训练输入哈希缓存。

两项标量选择只接触当前外层训练集的 550 条 OOF 记录。外层标签只在预测冻结后评分；测试样本不会参与阈值选择。所有六折独立选择的指标优势阈值均为 0.10，证据差距则各折不同。

本次仍是已知 v11 数据上的开发实验。上一轮错误分析促成了规则设计，因此不能把它称为全新、从未观察过的独立测试集。

## 三个预先固定的调用样本组

- `historical_72`：用原始代码和重拟合的相同超图，重建历史本地竞争候选选择与每折 12 次预算。覆盖历史全部 56 个发生预测修改的样本。
- `previous_uncertainty_72`：上一轮补充消融固定的 72 个上游不确定样本，不重新挑选。
- `fresh_random_72`：从上述两组之外，按固定 seed、折编号和案例 ID 的 SHA256 排序选每折 12 例。该样本组在本轮 LLM 输出前冻结，未按难度、根因或答案挑选。

历史组和上一轮组重合 27 例；随机组与它们无重合，三个组共涉及 189 个不同样本。各组分别报告，不能把三组共 216 个计数视为 216 个独立样本。

## LLM 对照与输出规则

每个入选样本比较三条路径：完整四候选池、原始一至两候选池、训练校准的保守候选池。配置沿用官方 Codex CLI、GPT-5.5／xhigh，独立临时对话，禁止工具调用。提示词、输出约束和证据卡片构造均与上一轮一致；两条路径中的共同证据内容不变。

主要候选筛选比较中，三条路径都在弃权／非法输出／接口失败时回退到同一个超图首选，防止回退规则混入候选池效应。

另按事先冻结的完整流程定义计算：本地校准规则处理全部 660 例；LLM 在每个固定的 72 例安排上进行仲裁，接受有效选择，其余保留本地输出。这一统计衡量完整流程，不单独归因于候选筛选。

完全相同的输入、提示词、输出约束和模型设置共享一份模型决策，避免把随机波动误当成代码效果，并减少重复调用。上一轮已保存的有效结果可按请求哈希复用；模型选择较差不会触发重试。567 个样本／方法决策对应 396 个不同输入，其中 144 个已有记录，本轮新增 252 次实际调用。

## 文件

- `protocol.json`：模型、样本安排、选择准则、源代码、数据、论文和图片指纹。
- `calibration/*.json`：每折完整训练 OOF 记录、排除的外层案例编号、阈值及训练选择审计。
- `prepared.json`：冻结的全部候选、预测、样本组和盲化模型请求。
- `deterministic_analysis.json`：全量本地消融和候选保留率。
- `new_model_calls.jsonl`：仅本轮实际新增模型调用。
- `decisions.json`：包含复用结果在内的完整逐方法决策，全部完成后生成。
- `analysis.json`、`paired_case_audit.csv`：最终分组分析与逐例对照，全部完成后生成。

准备阶段曾修正一次卡片集合接口错误：将总机制卡片库改为当前数据集的卡片集合。发生在准备完成和任何本轮 LLM 调用之前，原始协议快照及修复说明已保存；没有依据评估结果更改规则。
