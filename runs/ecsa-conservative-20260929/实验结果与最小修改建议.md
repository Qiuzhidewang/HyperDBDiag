# 本地结构化判别器的保守改动实验

2026-09-29，全部完成。新增 252 次官方 GPT-5.5／xhigh 调用，236 次有效选择、16 次有效弃权，无接口失败或非法输出。连同可复用的 144 份既有有效决策，共支持 189 个不同案例上的 567 个方法决策。论文、图片、旧代码和历史报告均未修改。

**结论：可以保留现有架构与流程图，通过改判阈值校准和自适应候选保留，增强本地判别器的作用。新的候选筛选在三组中相对全候选 LLM 分别净增加 1、2、0 例正确；旧筛选在不同样本组上的表现差异很大，不能概括为一直有害。当前证据支持保守改动的方向，但不支持宣称新完整流程在任何调用安排下都优于每个消融。**

## 1. 实际改了哪些代码细节

新增可选实现 `src/conservative_evidence_judge.py`，原实现保留作为对照。它复用原来的画像、证据卡片、直接语义规则和评分公式，没有新训分类器、增加证据来源、改变超图或修改 LLM 提示词。

1. **证据不足时保留完整池。** 原接口把“没有发现足够强的 challenger”表示为只交出超图首选。新接口在这一情况下保留完整四候选池，避免把证据不足转化为排除其他解释。
2. **按证据差距保留候选。** 有足够强的本地判断时，保留超图首选、本地首选，以及与最高证据分数距离不超过校准阈值的候选。候选数可以是 2、3、4，不固定为两个。
3. **指标模式改判阈值只在训练侧选择。** 保持直接语义提名规则不变，将原固定的 0.05 模式优势阈值改为训练内 OOF 选择。六个外层折均独立选到 0.10；没有使用外层标签选这个值。

每个外层折内部完整交叉拟合五个训练组，超图和本地画像都排除内层验证组及外层测试组。候选保留阈值要求训练 OOF 中总体至少保留 99%、每个组至少保留 97% 的“原完整池已包含的正确候选”。这是经验校准准则，不是理论保证。

对应的每折证据差距依次为 0.06066、0.09096、0.07921、0.08029、0.08737、0.11407。所有协议和输入均在本轮 LLM 调用前冻结。准备阶段修复过一次总卡片库与数据集卡片集合的接口不匹配，发生在任何本轮模型调用之前，修复记录已保留。

## 2. 三批固定样本及比较边界

每批都是每折 12 例、合计 72 例：

- **历史调用组**：重建原代码实际挑选 LLM 仲裁案例的规则，覆盖历史全部 56 个发生预测修改的案例。
- **上一轮不确定样本组**：完整复用上一轮补充消融的 72 例。
- **新随机组**：从前两组之外按固定哈希顺序选择，在本轮输出产生前冻结，不按标签、根因或结果挑选。

历史组与上一轮组重合 27 例，新随机组与两者均无重合，三个组共 189 个不同案例。随机组仍来自同一 v11 数据集，不是一个新的独立数据集。各组分别报告，不把它们当成 216 个独立样本合并证明显著性。

以下“旧筛选”是旧候选规则在本次统一提示词和仲裁设置下的结果；历史组也只复用了历史样本安排，不能把表中的数字解释为原论文旧运行的逐次复现。

候选筛选的主要比较统一使用超图首选作为弃权回退；另外单独报告“本地输出作为回退”的完整流程。这样可以区分候选池效应和回退规则效应。

## 3. 主要结果：候选筛选对仲裁的影响

表中为 **Exact / Component micro-F1（%）**；三条 LLM 路径的共同证据、提示词、模型和输出约束完全一致。

| 样本组 | LLM 完整候选池 | 旧筛选＋LLM | 新保守筛选＋LLM |
|---|---:|---:|---:|
| 历史调用 72 例 | 88.89 / 95.72 | **91.67 / 96.88** | 90.28 / 96.09 |
| 上一轮不确定 72 例 | 83.33 / 92.64 | 72.22 / 86.21 | **86.11 / 93.51** |
| 新随机 72 例 | **87.50 / 95.11** | 86.11 / 92.86 | **87.50 / 95.11** |

以 Exact 正确数计，新筛选相对完整候选 LLM：

- 历史组：纠正 2 例、改错 1 例，净增加 1 例；六折分块 bootstrap 的探索性增益区间为 [−2.78, +5.56] pp。
- 上一轮组：纠正 2 例、无新增改错，净增加 2 例；区间为 [0.00, +5.56] pp。
- 随机组：72 例的最终根因集合逐例相同；这不是证明未来数据永远等价。该组 59 例的新筛选请求与完整池请求相同，共享同一份决策；其余 13 例虽输入不同，最终预测也相同。

新筛选相对旧筛选，三组分别净减少 1 例、增加 10 例、增加 1 例。历史组是有利于原规则发挥作用的样本区域，新规则并未全面超过它；最明显的修复发生在上一轮暴露过度收缩问题的不确定样本组。该组曾用于分析设计问题，因此不能将其改善单独作为新独立验证。

## 4. 本地判别器的独立贡献

全部 660 例，不调用 LLM：

| 方法 | 正确数 | Exact | Component F1 |
|---|---:|---:|---:|
| 超图基线 | 380/660 | 57.58 | 74.17 |
| 原规则直接读出 | 539/660 | 81.67 | 89.72 |
| 训练校准后的本地读出 | **546/660** | **82.73** | **90.12** |

新的阈值策略相对原直接读出纠正 9 例、改错 2 例，另有 1 例改变后仍错误，净增加 7 例正确。局部规则的价值已经可以独立测量，原来的两行 57.58/74.17 不再是唯一可能的无 LLM 读出。

“原规则直接读出”与“历史原始 local 行”应区分：前者输出旧规则提名的候选，后者仍保持超图首选。新实现只在超图已经生成的候选中选择，没有独立生成新根因。

## 5. 收缩程度与正确候选保留率

| 范围 | 完整池平均候选数 | 旧筛选平均候选数 | 新筛选平均候选数 | 完整池包含正确答案 | 旧筛选保留 | 新筛选保留 |
|---|---:|---:|---:|---:|---:|---:|
| 全部 660 例 | 4.00 | 1.32 | 3.45 | 636 | 552 | 631 |
| 历史调用 72 例 | 4.00 | 2.00 | 2.22 | 69 | 67 | 68 |
| 上一轮不确定 72 例 | 4.00 | 1.47 | 3.25 | 65 | 53 | 65 |
| 新随机 72 例 | 4.00 | 1.21 | 3.69 | 71 | 64 | 71 |

全量上，新规则保留 631/636，即 **99.21% 的上游可恢复正确答案**，旧规则为 86.79%。新规则相对四候选池减少 13.71% 的候选条目；历史调用组减少 44.44%。仍有 5 个全量正确候选被删除，不能宣称零损失。

候选数减少不等于 token 或时延按同比例减少。共同的画像和观测占输入的大部分；历史组新筛选逻辑输入 token 仅比完整池少约 2.25%，上一轮组约少 0.97%，随机组约少 0.38%。输出 token 在后两组反而增加。本实验不据此宣称整体调用成本稳定下降。

## 6. LLM 相对本地输出还能增加多少

采用事先规定的完整流程：本地校准规则处理全部案例；有效 LLM 选择替换本地输出，弃权／失败保留本地输出。

| 样本组 | 本地直接输出正确数 | 加 LLM 后正确数 | 成对变化 |
|---|---:|---:|---|
| 历史调用 72 例 | 66 | 65 | 0 例纠正，1 例改错 |
| 上一轮不确定 72 例 | 53 | 62 | 9 例纠正，0 例改错 |
| 新随机 72 例 | 63 | 63 | 4 例纠正，4 例改错；组成 F1 从 93.33 提升到 95.11 |

这说明 LLM 并非在任何已经被本地充分判别的样本上都能继续增加 Exact。当前结果提示，后续值得在训练侧校准仲裁触发条件，把预算用于本地尚未充分解决的候选。不能按这里的外层错误案例直接编写特例或挑选有利调用安排。

按三种预先固定的 72 例调用安排，完整流程在全部 660 例上的 Exact / F1 分别为：

| 调用安排 | 无 LLM 的本地流程 | 加入 LLM 的完整流程 |
|---|---:|---:|
| 历史安排 | 82.73 / 90.12 | 82.58 / 90.07 |
| 上游不确定安排 | 82.73 / 90.12 | 84.09 / 90.87 |
| 随机安排 | 82.73 / 90.12 | 82.73 / 90.31 |

这些数值完整列出，不选择其中最高的 84.09% 冒充已经独立验证过的最终正式配置。其余基线、本地规则全量处理与 LLM 限额处理的覆盖差异，也不能全部归因于候选筛选。

## 7. 可复核的收益与失败案例

- `case-0325`，真值 `implicit_conversion + missing_index`：全候选 LLM 只选了 `implicit_conversion`；本地保留两个候选后，仲裁选择正确组合。该案例说明合理筛选确实可以排除干扰。
- `case-0415`，真值 `implicit_conversion`：旧筛选和完整池 LLM 都输出 `implicit_conversion + missing_index`；新规则保留三候选后选对，说明不必固定只留一个 challenger。
- `case-0160`，真值 `missing_index + query_with_too_much_join`：新规则不作过强筛选、保留完整池并选对；旧筛选后只输出 `query_with_too_much_join`。
- `case-0580`，真值 `group_by + missing_index`：新仲裁弃权。若用统一超图回退，该例错误；用本地回退，该例正确。它说明回退规则必须单独报告。
- `case-0629`，真值 `missing_index + query_with_too_much_join`：本地读出和完整池 LLM 都正确，但新三候选仲裁只选择 `query_with_too_much_join`。这是新仲裁确实存在的改错，报告中保留，没有重试。

以上是决策与候选集合的事实核对，不把模型隐藏推理或单次输出解释当作因果证明。

## 8. 对论文与图片的最小修改建议（未写回）

可以保留架构和 ECSA 流程图，仍然是证据组织、本地判别与候选缩减、LLM 集合仲裁。图中没有把保留数限定为两个。

方法正文可以在现有局部筛选公式后补充如下两句，说明代码实际行为：

> When local evidence is insufficient to establish a reliable preference, the discriminator retains the original candidate pool. Otherwise, it retains the initial reference, the locally preferred candidate, and candidates within an evidence-score margin calibrated using grouped out-of-fold predictions from the training data.

中文对应：

> 当本地证据不足以形成可靠偏好时，判别器保留原候选池；否则，保留初始参考候选、本地优选候选及证据分数差距处于校准范围内的候选。改判阈值与候选保留范围仅通过训练数据的分组交叉验证确定。

消融设置还需简要明确本地无 LLM 的读出方式，以及无本地筛选的 LLM 使用完整候选池。若正式采用本地回退，还应补一句说明仲裁弃权时保留本地优选候选。

**数值一致性不能省略：** 目前主文图 5 展示诊断性能，图 6 展示 SQL／算子定位性能。架构图可以不动；若最终采用新方法并替换正式结果，表格及相关性能图的数据必须同步核对更新，不能保留旧数字而只换表 4。图的样式可以保留。诊断变化可能影响后续定位结果，本轮尚未重跑 SQL／算子定位与建议生成。

建议将本次保守版本作为下一步候选实现保留。方法本身无需大篇幅重写；正式实验表格的最终配置仍需统一调用策略，并完成受诊断变化影响的结果复核。本轮没有根据三组测试结果再改触发规则，也没有继续搜索直到某个版本在每组都胜出。

## 9. 验证与复现

- 新旧相关测试 23 项全部通过，记录见 `test_results.txt`。
- 所有 189 对应案例的公共证据逐项一致；模型输入不含测试标签、案例 ID 或论文对话。
- 每折校准的 550 个训练案例与 110 个外层测试案例编号无交集。
- 统计由独立集合计数计算，并与既有 Exact / micro-F1 函数逐项核对一致。
- 数据、方法代码、论文、图片和既有实验文件指纹均通过核验。
- 只进行了每个不同输入的一次模型推断；完全相同输入按哈希复用已有有效输出。六折区间为探索性统计，不主张新独立数据上的显著优势。
