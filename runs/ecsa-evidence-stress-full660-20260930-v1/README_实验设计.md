# ECSA 证据扰动全量扩展

本实验应用户要求，将已完成的 120 例初步检查扩展到现有全部 660 例。它回答两个问题：证据卡被扰动时，最终诊断是否仍限定在候选池内；候选池内的诊断是否随证据扰动而变化。论文与现有图表暂不修改，结果需经用户确认后才考虑写回。

## 范围与对照

沿用原有六个划分，每个划分 110 例，其中单根因 44 例、双根因 66 例。全部案例均纳入，不按历史诊断是否正确、模型置信度或候选数量挑选。

| 条件 | 覆盖案例 | 实际改变输入的案例 | 不同输入数 |
|---|---:|---:|---:|
| 原始证据 | 660 | 0 | 658 |
| 所有候选使用相同正证据 | 660 | 618 | 659 |
| 清空反证据 | 660 | 660 | 658 |
| 打乱正反证据 | 660 | 660 | 660 |
| 仅反转排列顺序 | 660 | 660 | 658 |
| 加入候选外根因诱导文本 | 660 | 660 | 658 |
| 原始输入单独重复 | 660 | 0 | 658 |

前三项扰动及顺序对照、诱导文本与初步实验完全一致。具体文本、种子、变换方法在冻结的 `protocol.json` 中。正证据统一条件中的 42 例原本就具有相同正证据，因此变换不会改变输入；保留这些案例并明确报告，不将其当作新的独立调用。

原始输入重复组覆盖全部 660 例，对 658 份不同原始输入各新增一次独立调用；完全相同输入共用同一份重复响应。三个原始输入完全相同的案例是 case-0339、case-0352、case-0636，均属于同一划分，真实标签均为 record_lock。主调用和重复调用使用不同的任务编号，重复结果绝不替换首次结果。协议中“每例一次重复”指案例覆盖范围，实际调用数以冻结的 `planned_clean_repeat_calls=658` 为准。

## 调用保存与复用

六种主条件共有 3960 个案例与条件组合，去除完全相同输入后为 3909 份输入。原 120 例的 713 份首次响应全部原样复用，包括弃权和非法响应。补齐 3196 次主调用，并新增 658 次重复调用，总计新增 3854 次调用。完成后应保存 4567 份响应记录，映射到 4620 个案例与条件组合。案例评估数量与实际模型调用数量分别报告。

模型、推理配置、提示词、输出格式、CLI 版本、超时设置、生产校验器和本地回退均与初步实验一致。扩展使用 24 路并发，原实验为 8 路；这一差异已在调用前记录，不据此比较延迟或吞吐量。所有新任务按预先固定的随机顺序执行，主条件和重复条件交错运行。只保存可见的结构化输出，不采集隐藏推理。

API 输入仅含候选与证据，不含案例编号、真实标签、历史答案或当前讨论。一次任务只进行一次应用层调用；保留客户端默认的传输重试。弃权、非法响应、接口失败各自计数，并按原实现回退。连续八次传输失败时停止安排后续调用，不用重新采样来替换不理想答案。

## 比较与限制

主指标以每组全部 660 例为分母，报告 Exact 和 F1；原始候选越界与最终结果越界分开统计。每组同时报告弃权、非法输出、接口失败、相对原始对照的改对／改错及预测变化数，并保留分折和原 120 例／新增 540 例的分组结果。原始重复组用于观察相同输入的调用波动，与顺序对照一并解释；一次额外重复不能完全识别所有随机因素和顺序因素。

输入扰动发生在本地筛选之后，候选池和本地结果固定。独立指标轨迹、语义观察、训练模式与机制卡继续提供信息。因此，诊断没有明显变化不等于模型完全忽略正反证据，也不等于本地判别器无效；本实验不能替代各模块的消融。候选外诱导只使用一条固定文本，不能解释为覆盖所有攻击。零次观测越界也不意味着任意输入下都不会出错。最终诊断正确率包含本地回退；另保留仅成功选择候选时的指标。

扩展是在已知初步结果后进行的，使用的是现有 660 例数据，不宣称外部泛化。先冻结实验规则，再执行新增调用；不根据新增结果调整模型、提示词、扰动强度或判断标准。

## 核验与产物

- `protocol.json`、`prepared.json`：冻结协议及全部输入映射。
- `reused_primary_responses.jsonl`、`new_responses.jsonl`：原始可见响应及校验结果。
- `synthetic_guard_checks.json`：全部 660 例上的 4620 次人工构造校验检查，与真实 LLM 调用结果分开。
- `predictions.json`、`results.json`、`summary.csv`、`RESULTS_实验结果.md`：完成后统一生成，不发布未完成的分组准确率。
- `independent_audit.json`：独立重建输入变换，验证原有结果未变，重放生产校验器，重算指标。
- `completion.json`：完成状态和产物文件指纹。

执行脚本：`scripts/run_ecsa_stress_fullcoverage.py`。独立核验脚本：`scripts/audit_ecsa_stress_fullcoverage.py`。原初步实验、主方法代码、论文、已有图表和历史结果均受文件指纹保护。
